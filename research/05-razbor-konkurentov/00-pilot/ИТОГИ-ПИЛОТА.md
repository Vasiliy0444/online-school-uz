## Meta Ad Library — работает, с двумя важными поправками

1. **ID страницы Ad Library ≠ ID профиля.** В прошлом скане в колонке `handle` лежит ID профиля
   (`100093860176934` — ссылка `facebook.com/100093860176934/`). По нему список объявлений пустой.
   Нужен `view_all_page_id` = `page_id` из JSON объявления (`111238895346791`). Проверено во встроенном браузере.
2. **Первые 30 объявлений приходят прямо в документе страницы** (JSON внутри `<script type="application/json">`),
   без прокрутки. Порядок — сортировка Meta «по показам» (`sort_data[mode]=total_impressions`).
   Поля: `ad_archive_id`, `page_id`, `page_name`, `start_date`, `end_date`, `is_active`, `collation_id`, `collation_count`,
   `publisher_platform`, `snapshot` (`body`, `cards`, `images` c `original_image_url`, `videos` c `video_hd_url`/`video_sd_url`/
   `video_preview_image_url`, `cta_text`, `cta_type`, `link_url`, `caption`, `display_format`, `page_like_count`, `page_categories`).
   Показы и расходы для Узбекистана пустые (`impressions_index: -1`, `spend: null`).
3. **Счётчик «~N results»** читается из текста страницы: у Qadam.online — **~160 активных объявлений в UZ**
   (скан 15–16.09 по ключевым словам видел 38).
4. **Прокрутка упирается в лимит.** При догрузке через `/api/graphql/` Meta 34 раза ответила
   `Rate limit exceeded` (код 1675004). Сбор остановлен в 17:37, пауза. Вывод: сбор без прокрутки, паузы 25–45 с
   между загрузками, на лимите — стоп (реализовано в `../meta_collect.py`).
5. **Код 403 у документа — норма.** Первым приходит короткая страница с JS-проверкой (481 байт), браузер её выполняет
   и получает настоящую страницу (200). Так ведёт себя любой обычный браузер; ничего не обходим.
6. **Видео качаются по прямым ссылкам CDN** из JSON: 5 из 5 файлов, HD, 5–35 МБ, 27–190 секунд.
7. **Фильтр по датам** (`start_date[min]`, `start_date[max]` — названия параметров найдены в коде страницы) проверен
   18:10 двумя загрузками без прокрутки (`meta_slice_test.py`, `meta/slice-test-111238895346791.json`), лимита не было:
   - окно 01–30.04.2026 → «~28 results», разобрано 28, из них 23 запущены в апреле, 5 — раньше (с 24.11.2025);
   - окно 01–16.09.2026 → «~160 results» — весь список.
   Фильтр не делит объявления строго по дате запуска, но окна по месяцам дают порции до 30 объявлений, которые приходят
   в документе без прокрутки. **Способ полного сбора для короткого списка:** окна по месяцам с первого запуска до сегодня,
   окно со счётчиком больше 30 — дробить; полноту проверять объединением окон против общего счётчика «~N results».
8. **Поиск по ключевым словам 16.09 урезан.** «bepul vebinar» — «~17 results» (15.09 было «~120»), «vebinar» — «~26» (было «~130»);
   16 из 17 и 22 из 24 объявлений запущены в сентябре 2026. Сортировка по показам не меняет счётчик; обычный встроенный браузер
   тоже показывает «~17 results». Причину (изменение у Meta или ограничение для нашего подключения) проверить нечем.
   Вывод: поиск по словам — только дополнительный источник свежих запусков; основа мастер-списка — 292 рекламодателя
   скана 15.09, бриф и карта блогеров. Прогон 124 запросов остановлен после 2 загрузок (18:14), позже перезапущен в конце очереди.
9. **Страница одного объявления** (`?id=<library_id>` с теми же фильтрами) отдаёт в документе объявления этого рекламодателя
   (до 30) с `page_id` и счётчиком: для Barno Askarova — 15 объявлений, `page_id` 206836704709082 (ID профиля в скане 03 —
