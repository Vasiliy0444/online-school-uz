# Подключение своего бизнеса: Meta Ads → Codex

Цель: по ТЗ создавать новые рекламные объекты на паузе, выдавать тебе фактические настройки и превью, оставлять запуск за тобой. Локальная часть готова; доступ к Meta ещё не получен. [Исследование](ИТОГ.md), [состояние проверки](verification.json).

## Шаг A. Собрать бизнес-активы

В Business Settings найди нужный Business Portfolio, рекламный аккаунт, Facebook Page, связанный Instagram и Pixel/Dataset, если цель использует сайт. Убедись, что они принадлежат твоему бизнесу или ему предоставлен нужный доступ. Подготовь публичные ID, валюту и часовой пояс кабинета. Оплата, ограничения аккаунта и источник конверсии должны позволять нужную цель. [Требования Meta CLI](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-cli/setup/get-started).

Эти ID можно передать в чат. **Пароль, access token и App Secret в чат не передавать.** В проекте не хранить клиентские списки без отдельной договорённости об обработке данных.

## Шаг B. Выбрать приложение Meta

Если у тебя уже есть Developer App, сначала передай его публичный App ID: проверим, подходит ли оно и есть ли в нём нужный use case. Если нет — в [Meta for Developers](https://developers.facebook.com/apps/) создай приложение для своего Business Portfolio с use case **Create & manage ads with ads MCP server**. Для выбранного сочетания MCP и CLI нужно подтвердить наличие требуемых разрешений Marketing API в Dashboard; названия экранов могут меняться. [Официальная инструкция MCP](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-get-started), [официальная инструкция CLI](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-cli/setup/get-started).

Для собственных активов начинаем с доступного приложению уровня, не оформляем сразу продукт для клиентов. Если Meta потребует проверку приложения или бизнеса для нужного уровня доступа, завершаем именно этот процесс. **Отсутствие необходимости в App Review пока не подтверждено.** [Различия уровней доступа](https://developers.facebook.com/docs/marketing-api/access).

## Шаг C. Выдать доступ Employee System User

В Business Settings → Users → System Users создай системного пользователя с ролью **Employee**. Назначь только нужный рекламный аккаунт с правом управления, Page и остальные активы, необходимые кампании. Для MCP не выбирай роль Admin: она не поддерживается сервером. [Подключение MCP](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-get-started), [типы System User](https://developers.facebook.com/docs/marketing-api/businessmanager/systemuser/types).

Сгенерируй токен для выбранного приложения. Базовые scopes для записи через MCP: `ads_mcp_management`, `ads_management`; для доступа к страницам и креативам проверь `pages_show_list`, `pages_read_engagement`, `pages_manage_ads`, для Instagram — `instagram_basic`, если он нужен. `business_management` добавляй для операций с бизнес-активами или правилами, которые действительно его требуют. Не выдавай catalog permissions для кампании без каталога. Зависимости scopes и доступность проверяй в Dashboard. [MCP scopes](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-get-started), [CLI scopes](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-cli/setup/get-started), [permissions reference](https://developers.facebook.com/docs/permissions/reference).

Выбери ограниченный срок токена и запиши дату обновления в менеджере паролей. «Постоянный» токен может быть недоступен или отозван, поэтому не рассчитываем на бессрочность. При наличии условий Custom Audiences их принимает человек в кабинете. [Генерация токенов](https://developers.facebook.com/docs/marketing-api/system-users/install-apps-and-generate-tokens), [Custom Audiences](https://developers.facebook.com/documentation/ads-commerce/marketing-api/audiences/guides/custom-audiences).

## Шаг D. Сохранить токен локально

В локальном интерактивном терминале, из корня этого проекта, выполни:

```sh
/Library/Frameworks/Python.framework/Versions/3.13/bin/python3.13 infra/meta-ads/credentials.py store
```

Команда предложит скрытый ввод. Вставь токен туда. Он сохранится в `~/.config/meta-ads-codex/access-token` вне проекта с приватными правами. Команда не принимает токен аргументом. Проверить наличие без вывода значения:

```sh
/Library/Frameworks/Python.framework/Versions/3.13/bin/python3.13 infra/meta-ads/credentials.py status
```

Не запускай вручную действие `headers`: оно предназначено для передачи заголовка в Codex. Не вставляй токен в `.codex/config.toml`, JSON-ТЗ, команды shell или чат. В текущей конфигурации уже задан `http_headers_helper`, значение токена в неё не записано. [Код хранения](../../infra/meta-ads/credentials.py), [проектный MCP](../../.codex/config.toml).

## Шаг E. Поставить серверные ограничения, если доступны

В Meta Business Suite → Settings → Integrations → Ads MCP server выбери только нужный кабинет и разрешённые действия. Если раздел отсутствует, возможность для аккаунта **не подтверждена**, этот шаг нельзя считать выполненным. [Business Help](https://www.facebook.com/business/help/1456422242197840).

В доступном интерфейсе правил задай запрет изменения delivery status и максимальный бюджет, который **ты выберешь**. Если интерфейс не предоставляет нужную детализацию, используем документированный Ads API после чтения существующих правил и сверки scope. Это отдельная запись настройки, пока не выполненная. Спецификация предусматривает:

- запрет статуса: `action=edit_status`, `trigger_type=always`, `status=active`;
- предел бюджета: `action=edit_budget`, `trigger_type=absolute_max`, `metadata.max_value_cents`, `metadata.budget_dimension=both`, `status=active`.

Названия полей и смысл правил взяты из [официальной документации Meta](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-rules-best-practices). Предел нужно сверить с валютой и денежной единицей аккаунта. После записи — прочитать правила обратно. Это ограничение MCP, оно не запрещает твой ручной запуск в Ads Manager и не изолирует произвольные Graph API/CLI команды.

## Шаг F. Переподключить и принять доступ на чтение

Перезапусти подключение MCP в Codex или заново открой проектный чат. Автоматический `codex mcp login` здесь не выбран: проба DCR была отклонена Meta. [Зафиксированная ошибка](verification.json).

После этого Codex должен выполнить следующий протокол приёмки:

- Получить авторизованный `tools/list`. Сопоставить фактические имена и схемы с allowlist; сохранить схемы без токенов. Добавлять загрузочные инструменты только после проверки.
- Прочитать рекламный аккаунт и его валюту/часовой пояс; сверить с ТЗ.
- Прочитать Page, Instagram identity, доступные источники конверсии и существующие аудитории.
- Проверить доступность правил MCP; если они заданы, прочитать их фактическое состояние.
- Подтвердить, что инструменты активации, общего изменения существующих объектов и boost не доступны в этом подключении.

Имена текущего allowlist взяты из публичного каталога, наличие в твоём аккаунте пока **не проверено**. Если сервер не отдаёт необходимые поля/инструменты, агент сообщает конкретный пробел; не подменяет аудиторию, ставки или цель без согласованного изменения ТЗ. [Конфигурация](codex-mcp.toml), [каталог Meta](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-tools-ad-creation-and-management).

## Шаг G. Проверить формат и собрать кампании по ТЗ

Передай заполненный [шаблон ТЗ](ТЗ-ШАБЛОН.md) и реальные файлы. По нему готовим локальный manifest: кампании, группы, аудитории, креативы, тексты, бюджеты и ставки. Сначала валидируем сочетания полей без записи. Для выбранного формата проверяем полный цикл: загрузка → создание на паузе → чтение фактического объекта и превью. Этот тест остаётся в scope твоего ТЗ; фиктивную рекламу создавать не нужно.

Для одиночного локального креатива подготовлен helper. Копию [creative.example.json](creative.example.json) заполни реальными ID/URL/текстом и путём к медиа. Локальная проверка, **без обращения к Meta**:

```sh
/Library/Frameworks/Python.framework/Versions/3.13/bin/python3.13 infra/meta-ads/prepare_creative.py --spec /absolute/path/creative.json --preview
```

После локальной проверки команда без `--preview` загружает файл и создаёт креатив через официальный CLI. Её выполняет агент в рамках выданного ТЗ; она ещё **не проверена на реальном кабинете**. `--status=PAUSED` фиксирован. Для карусели, catalog и других форматов сначала проверяем MCP schema; текущий локальный helper их не реализует. [Helper](../../infra/meta-ads/prepare_creative.py), [Meta CLI: форматы](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-cli/ad-creatives).

Дальнейшая сборка идёт только в новые paused-объекты. Связи и ответы сохраняем по мере создания. При таймауте или частичной ошибке сначала читаем кабинет и ищем уже созданные ID; **автоматический повтор записи запрещён**. Клиентские списки добавляем только в созданную для данного ТЗ аудиторию через предварительно проверенный инструмент, который не может изменить используемую живую аудиторию.

## Шаг H. Пакет согласования и запуск

Агент передаёт:

- список фактически созданных campaign/adset/ad/creative/audience ID;
- прочитанные статусы, бюджеты, ставки, расписания и часовой пояс;
- тексты, ссылки, UTM, Page/Instagram identity и превью каждого формата;
- таргетинг, исключения, настройки Advantage+ и оптимизацию/событие;
- ошибки, предупреждения Meta и всё, что осталось **не проверено**;
- ссылку на нужный кабинет Ads Manager и краткую инструкцию включения объектов.

Ты согласовываешь и включаешь нужные объекты в Ads Manager. После включения Meta ещё может завершать модерацию; успешная сборка не гарантирует показ или результат рекламы. [Статусы и проверка объявления](https://developers.facebook.com/documentation/ads-commerce/marketing-api/reference/adgroup).

## Что нужно от тебя сейчас

Публичный App ID существующего приложения либо сообщение «приложения нет». Затем — завершить выдачу доступа и сохранить токен через скрытый локальный ввод. После этого можно принять соединение и передать первое ТЗ. Секреты в чат не нужны.
